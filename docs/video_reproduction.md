# Video reproduction and strict-release procedure

## Scope

The video pipeline supports two evidence levels:

1. **Editorial draft reproduction** rebuilds the sequence, timing, graphics,
   captions, and mix from whichever documented upgrade/fallback assets are
   present locally. This is useful for iteration but is not a release proof.
2. **Strict release reproduction** binds one clean tagged source revision, one
   selected tier per beat, every non-Git input, generation evidence, rights
   attestations, automated QC, and the final outputs to SHA-256. Curated source
   is read from commit blobs, not from the index or worktree. It fails rather
   than substituting a missing input.

ElevenLabs speech and music generation is nondeterministic. Regenerating a
provider output creates a new media version, duration, edit decision, and hash.
Bit-identical assembly therefore requires the exact selected binary masters;
the text and prompts alone support procedural/editorial reproduction, not byte
identity.

## Public source and external assets

The public Git source comprises:

- the explicit render/release allowlist under `scripts/video/`: the three
  `anim_*.py` builders, assembly/audio/beat/caption/common/overlay/QC modules,
  `release.py`, `render_v2.py`, `stills_05_07.py`, and `test_release.py`;
- `video/README.md`, `video/CREDITS.md`, and this guide;
- `video/narration_script_v2.md` and `video/segments_v2/*.txt`;
- `video/build/render_motif.py` and
  `video/build/music_v2_composition_plan.json`;
- the manifest schemas/templates under `video/manifests/`;
- `docs/storyboard.md` and `docs/edit_plan.md`.

The storyboard and edit plan are historical production records, not normative
release specifications. They intentionally preserve some superseded draft
language, including the former 425-band wording and Esri capture route. The
strict validator, this guide, and the frozen release contract supersede them.

Generated speech, music, motif/video masters, beat clips, captures, temporary
WAVs, logs, QC frames, and final videos remain ignored by Git. A strict release
always copies the assembled picture and `vo_master.wav` into `qc/replay/` so
the claimed timing gates can be rerun. It copies the exact selected media
masters into `masters/` only when `distribution.include_media_masters` is true.
If that is false, the frozen contract must name the matching immutable Zenodo
DOI or record URL containing those masters.

## Current release status

The templates are deliberately blocked. They do not assert a source tag,
archive DOI, ElevenLabs account plan, voice rights, generation IDs, non-beta
status, terms snapshot, or final claim approval. Historical drafts are not
release evidence. Do not change `status` to `frozen` until those fields are
verified and the narration/graphics agree with the final scientific claim set.

## Rendering inputs

The frozen contract requires these classes of input:

- all eight submission figures used by the edit;
- the timed narration script and nine per-beat text files;
- exactly nine selected narration masters;
- one selected music master and its composition plan;
- the procedural motif master;
- exact pre-rendered beat assets for any beat whose tier is `upgrade`;
- the Tanager-derived 1920×1080 composites for beats 05 and 07;
- one complete TTS generation/history record per selected narration segment;
- one complete music generation, terms, and editorial-selection record.

The release validator rejects absolute paths, `..`, symlinks, non-regular
files, duplicate paths, missing roles, malformed SHA-256 values, and hash
mismatches. The eight scientific figure paths and ten narration-text paths are
closed allowlists; adding or removing one requires a reviewed code/contract
change rather than a silent manifest edit.

The contract is accepted only at `video/manifests/release_contract.json`.
`release.id` must equal the exact Git tag, the canonical bundle name is
`tanager-rocks-video-<release.id>`, and pseudo-refs such as `HEAD`,
`FETCH_HEAD`, `ORIG_HEAD`, or any `refs/*` name are not exact tags. Frozen beat
records admit only the runtime-approved tier/path/null combinations: beat 03/04
upgrades use their own canonical paths, beats 05/07 use the frozen Tanager stills,
and generated fallback/designed beats have no source path except beat 00's frozen
motif. `render.json` binds each beat to its tier, source path, and source hash
rather than recording tiers alone.

## Redistribution-safe map policy

A local-only Playwright capture utility requests Esri World Imagery and is
intentionally excluded from the public Git allowlist. It may be retained for
internal editorial drafts. The strict release policy accepts only:

```text
beat 05  tanager-still  video/build/v2/fallback_05.png
beat 07  tanager-still  video/build/v2/fallback_07.png
```

Those composites are generated by `scripts/video/stills_05_07.py` from
Tanager-derived figures and repository-native legends. Strict mode rejects an
Esri capture even if the capture exists and has a supplied hash. Any future
change to this policy needs a new rights review and an explicit code revision.

## Preparing generation evidence

Copy the templates without overwriting any prior evidence:

```bash
cp video/manifests/tts.template.jsonl \
  video/manifests/tts.jsonl

cp video/manifests/music.template.json \
  video/manifests/music.json

cp video/manifests/release_contract.template.json \
  video/manifests/release_contract.json
```

For TTS, create exactly one `selected: true` JSONL record for each of the nine
segment keys. Record the text and output paths/hashes, provider generation ID
and UTC time, account plan at generation, non-beta confirmation, voice identity
and status, applicable terms URL, model/output format, request settings, and the
editorial selection decision. Preserve nulls only for optional provider fields
such as a seed that was unavailable, and name that limitation in
`settings.unavailable_fields`.

For music, record the selected output/path hash, generation ID/time, plan,
non-beta status, `music_v2`, `force_instrumental: true`, terms URL/retrieval
time/snapshot hash, and editorial decision. The validator cross-checks the
music-output and composition-plan hashes against the release contract.

The DOI evidence has two distinct bundled records:

- `evidence/doi.json` is the reviewed DOI packet. It names the minted Zenodo
  record, DOI URL, record URL, retrieval/review times, reviewer, and the path
  and SHA-256 of the unchanged provider export.
- `evidence/zenodo-record.json` is that provider-origin API export. It must
  include a non-empty `files` array with each provider key, positive size, and
  `md5:` or `sha256:` checksum.

Finalization resolves the DOI and retrieves the Zenodo record again.
`READY.json` binds the requested/resolved DOI URLs and status plus the live
Zenodo record ID, API URL, response SHA-256, and file/checksum inventory. A
manually assembled self-consistent packet cannot replace that live gate.

These records contain provenance, not credentials. Never include API keys,
billing tokens, full account exports, or Doppler output.

## Freezing the release contract

Fill `release_contract.json` only from checked evidence:

1. Correct and approve all narration, captions, callouts, and end-card claims.
2. Create the clean release commit and tag. Record the full 40-character commit
   and tag; set `source.dirty` to `false` only in a clean checkout. Set
   `release.id` to that tag and `release.bundle_name` to
   `tanager-rocks-video-<release.id>`.
3. Reserve or mint the archive DOI and record its full `https://doi.org/...`
   URL. Strict mode injects this value into the end card; `DOI pending` cannot
   pass release mode.
4. Record the final repository URL and output basename.
5. Compute SHA-256 for every listed input after the files are frozen.
6. Complete the five rights/claims attestations only after their supporting
   review is done. Name the operator as trust root and bind the provider
   account-plan and generation-plan records. Validation checks packet
   completeness and congruence; code does not establish legal rights.
7. Decide whether exact media masters may be copied into the release bundle.
   If not, record their immutable external release-asset URI.
8. Change `status` from `template` to `frozen` last.

The canonical contract locator and hash are bound into `render.json`, and the
contract is copied into the bundle.

## Non-rendering preflight

Run this before allocating render time:

```bash
uv run python scripts/video/render_v2.py \
  --release \
  --preflight-only \
  --contract video/manifests/release_contract.json
```

Preflight verifies:

- the contract kind/version/status and every non-null gate;
- the full commit SHA, clean worktree, and tag-to-commit identity;
- every curated path exists as a regular-file blob at that exact commit;
- exact input paths, roles, file types, and SHA-256 values;
- all nine narration selections and the one music selection;
- selected TTS/music evidence against the frozen text/audio/plan hashes;
- the ten beat tiers, including the Tanager-only 05/07 policy;
- the archive DOI, repository URL, and external-master route.

Failure is terminal for that contract. Correct the source evidence and issue a
new contract version; do not weaken the validator to make a stale artifact pass.
Git status is not the byte authority for curated source: skip-worktree or index
flags cannot substitute worktree bytes because the capsule is populated from
`<commit>:<path>` blob content. Contract inputs that overlap curated source,
such as narration text and the music plan, must hash to those same committed
bytes.

## Strict rendering

After preflight passes:

```bash
MPLCONFIGDIR=/private/tmp/tanager-video-mpl \
  uv run python scripts/video/render_v2.py \
    --release \
    --contract video/manifests/release_contract.json \
    <release-id>
```

`<release-id>` must equal `release.id`. The renderer:

1. reads every curated source path as a regular-file blob from the frozen
   commit, writes those exact bytes into the capsule, and copies the canonical
   contract and selected non-Git inputs using descriptor-relative
   `O_NOFOLLOW` opens; worktree source bytes never populate the curated layer;
2. seals every execution-capsule inode with Darwin `UF_IMMUTABLE`, verifies the
   bytes and flags, and runs `python -I` with cwd/imports confined to it;
3. renders from the contract-selected narration, beat sources, figures, and
   music, then writes a strict SRT whose verifier requires consecutive cue
   indices, valid `HH:MM:SS,mmm` values, positive non-overlapping durations,
   monotonic order, and non-empty text;
4. accepts exactly one video and one audio stream in the final MP4, maps and
   fully decodes both, fully decodes the single-stream assembled picture and
   VO master, and independently rechecks 30 fps, dimensions, picture/mux/VO
   timing, A/V agreement, loudness, true peak, and required caption text;
5. rechecks capsule bytes/seals and the live tagged checkout after worker use;
6. resolves the DOI over HTTPS and compares the authoritative Zenodo API
   record's file/checksum inventory with the frozen export and omitted masters;
7. verifies under a hidden finalizing name, writes `READY.json`, verifies again,
   and exposes the canonical name with Darwin `RENAME_EXCL`.

No prior release bundle is overwritten and a destination race fails atomically.
A failed final verifier leaves a dot-prefixed quarantine without `READY.json`
(or with `FAILED_FINAL_VERIFICATION.json`), so `verify-bundle` rejects it. Once
the canonical READY directory has been promoted, finalization has succeeded.
Failure to unseal or remove the now-private staging directory emits a
`ReleaseCleanupWarning`, preserves the READY result, and leaves the staging path
for explicit cleanup; it does not report the release as failed. If warning
filters promote that warning to an exception, the finalizer contains the
exception and writes the same residue path as a best-effort stderr advisory.
Warning or stderr reporting failure cannot retract the canonical READY result;
the untouched staging path remains the discoverable cleanup target.

Strict capsule sealing and no-replace promotion currently require macOS; strict
mode fails elsewhere rather than accepting chmod or check-then-rename. The
owner can deliberately clear `UF_IMMUTABLE`, so a malicious process running as
the operator is inside the trust boundary. Live HTTPS/provider responses and
the named operator remain trust roots. The manifest records the host Python
version and resolved executable path plus the first version lines reported by
`ffmpeg` and `ffprobe`; it does not hash or sign those host executables. Host
Python/FFmpeg binary identity and process integrity therefore remain residual
trust. Later offline verification checks the recorded packet's congruence, not
provider authenticity or legal rights.

## Release bundle

The promoted directory
`output/releases/tanager-rocks-video-<release-id>/` contains:

```text
tanager-rocks-video.mp4
tanager-rocks-video.srt
render.json
release_contract.json
SHA256SUMS
READY.json
LICENSE
NOTICE.md
CITATION.cff
CREDITS.md
evidence/tts.jsonl
evidence/music.json
evidence/doi.json
evidence/zenodo-record.json
qc/*.png
qc/replay/picture.mp4
qc/replay/vo_master.wav
masters/...                 # only when explicitly authorized
```

`render.json` records the source commit/tag, command, exact beat tiers and
source paths/hashes, all input/source/output hashes, worker-recomputed
environment and font identity, render settings,
generation evidence hashes, closed automated-QC names/messages, each frozen
narration source hash and probed duration, replay measurements, and the
still-pending human review. The picture and VO-master replay records must match
their generated-artifact hashes. `SHA256SUMS` covers every other file in the
bundle and the verifier rejects both missing and extra files.

Verify the bundle independently:

```bash
uv run python scripts/video/release.py \
  verify-bundle output/releases/tanager-rocks-video-<release-id>
```

## Human acceptance and publication gates

Automated checks cannot certify narration delivery, music masking, motion
comfort, scientific comprehension, attribution legibility, or the absence of
an awkward frame. A named reviewer must watch the full MP4 in real time with
captions on and off, inspect the credits and DOI, and record the result beside
the release artifact. The generated manifest deliberately retains
`qc.human_playback.status: pending`; do not describe the artifact as final until
that separate record is completed.

Publication remains a distinct operator gate. Committing source, rendering a
bundle, making a repository public, creating a GitHub release, archiving in
Zenodo, enabling Pages, and submitting the competition entry are separate
actions and require their own approvals and post-publication verification.

## Focused implementation checks

These checks do not render media:

```bash
.venv/bin/python -m pytest -q scripts/video/test_release.py

.venv/bin/ruff check \
  scripts/video/release.py \
  scripts/video/captions.py \
  scripts/video/test_release.py

.venv/bin/ruff format --check \
  scripts/video/release.py \
  scripts/video/captions.py \
  scripts/video/test_release.py

.venv/bin/python -m json.tool \
  video/manifests/release_contract.schema.json >/dev/null

.venv/bin/python -m json.tool \
  video/manifests/render_manifest.schema.json >/dev/null

uv run python scripts/video/render_v2.py \
  --release \
  --preflight-only \
  --contract video/manifests/release_contract.template.json
```

The pytest suite includes Draft 2020-12 schema validation, exact-tag and per-beat
schema/runtime parity probes, warnings-as-errors cleanup coverage, and
adversarial frozen-contract/render-manifest mutations. The tests, Ruff checks,
and JSON parses should pass. The template preflight must fail with the explicit
message that template contracts cannot render; a passing template preflight
would be a release-boundary defect.
